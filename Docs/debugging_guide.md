# 系统调试与故障排查手册

## 1. 模块化 Bring-up 流程

> 原则: 每次只增加一个模块，验证通过后再接下一个。严禁一次性连接全部模块后上电。

### 1.1 Stage 0: 最小系统验证

**目标:** 确认 MCU 正常启动、SWD 烧录可用、串口通信正常。

**接线:**

| ST-Link / USB-TTL | STM32F103C8T6 |
|-------------------|---------------|
| SWCLK | SWCLK |
| SWDIO | SWDIO |
| GND | GND |
| USB-TTL RX | PA9 (USART1_TX) |
| USB-TTL TX | PA10 (USART1_RX) |

**验证步骤:**
1. Keil MDK → Rebuild → 确认 0 Error, 0 Warning
2. Download → 复位 MCU
3. 串口终端 (115200-8-N-1) 应输出:

```
========================================
  STM32 Attitude & Servo Control System
  MCU: STM32F103C8T6 @ 72MHz
========================================
[INIT] IWDG watchdog...
[OK]   IWDG enabled, timeout ~2s
```

**失败排查:**
- 无输出 → 检查 TX (PA9) 是否连接到 USB-TTL 的 RX (交叉连接)
- 乱码 → 波特率不匹配，确认 115200

> **看门狗行为说明:**
> 1. IWDG 一旦启动，无法通过软件关闭，仅复位可停止。喂狗由 `Scheduler_Run()` 主循环每轮无条件执行；任何位置死循环超过 2s 即触发复位，串口输出 `[!] IWDG Reset Detected`，可作为死循环/卡死故障的定位依据。
> 2. 断点调试不会触发看门狗复位：启动时已调用 `DBGMCU_Config(DBGMCU_IWDG_STOP, ENABLE)`，内核被调试器暂停期间看门狗同步冻结，正常运行不受影响。

---

### 1.2 Stage 1: I2C 总线验证

**增加接线:**

| 模块 | STM32 |
|------|-------|
| OLED VCC | 3.3V |
| OLED GND | GND |
| OLED SCL | PB10 |
| OLED SDA | PB11 |

**验证步骤:**
1. 烧录，串口应在 `< 2s` 内打印 `[OK] MPU6050 WHO_AM_I = 0x68`（克隆芯片可能为 0x70/0x98，本工程已兼容并会打印 "clone, functional"）
2. OLED 显示 "System Ready" 及姿态数据
3. 检查 OLED 右下角心跳指示 (`*` 以 1Hz 闪烁)

**WHO_AM_I 返回 0xFF 或 0x00 时:**
- 万用表测量 SDA/SCL 对 VCC 电阻 → 应约为 4.7kΩ (模块板上拉)
- 检查 PB10→SCL, PB11→SDA 是否接反
- 断开 OLED，仅保留 MPU6050，排除总线多从机冲突

---

### 1.3 Stage 2: 传感器数据验证

**目标:** 确认 MPU6050 原始数据正确，姿态解算输出合理。

**验证步骤:**
1. 传感器水平放置 → OLED 显示 `P: 0.0 R: 0.0` (误差 ±2° 内)
2. 缓慢前倾 → pitch 正值增大
3. 缓慢左倾 → roll 正值增大
4. 连接 VOFA+ → FireWater 协议 → 观察 7 通道波形（详见 2.5 节完整配置步骤）

**角度漂移 (静止时缓慢变化):**
- α 值过大 (如 0.995) → 减小至 0.96~0.98
- 陀螺仪零偏未校准 → 在静止时读取 gyro 均值，初始化时减去

**角度跳动:**
- DLPF 带宽过高 → 检查 CONFIG 寄存器 (0x1A)，确认值为 0x06 (5Hz)
- 供电纹波 → 在 MPU6050 VCC-GND 间加 0.1µF 去耦电容

---

### 1.4 Stage 3: 舵机 PWM

**增加接线:**

| SG90 舵机 | 连接 |
|-----------|------|
| 橙 (信号) | PA0 |
| 红 (电源) | **外部 5V** (严禁接 STM32 3.3V) |
| 棕 (GND) | STM32 GND (必须共地) |

> 外部 5V 电源需 ≥ 2A。推荐在电源输出端并联 470µF 电解电容 + 0.1µF 瓷片电容。

**验证步骤:**
1. 上电 → 舵机自动归中 (90°)
2. 旋转编码器 → 舵机平滑跟随
3. 倾斜传感器 → 舵机动态跟踪角度变化

---

### 1.5 Stage 4: PID 参数整定

**方法: Ziegler-Nichols 临界比例度法 (工程简化版)**

1. 设 $K_i = 0, K_d = 0$
2. 逐步增大 $K_p$，直到系统出现等幅振荡，记录临界增益 $K_u$ 和振荡周期 $T_u$
3. 按规则计算:

| 控制类型 | $K_p$ | $K_i$ | $K_d$ |
|---------|-------|-------|-------|
| P | $0.5 K_u$ | — | — |
| PI | $0.45 K_u$ | $0.54 K_u / T_u$ | — |
| PID | $0.6 K_u$ | $1.2 K_u / T_u$ | $0.075 K_u \cdot T_u$ |

**在线调参 (本工程支持):**

短按编码器 SW 按键 (PB14) 循环切换模式:

```
MODE_RUN    → 正常运行，编码器调 setpoint
MODE_TUNE_KP → 旋转编码器调节 Kp (步长 0.1)
MODE_TUNE_KI → 旋转编码器调节 Ki (步长 0.01)
MODE_TUNE_KD → 旋转编码器调节 Kd (步长 0.05)
```

OLED 行 6 实时显示当前模式及参数值。VOFA+ 可同步观察 PID 输出 (ch5) 的响应变化。

**调参参考:**

| 现象 | 根因 | 调整方向 |
|------|------|---------|
| 响应迟缓 | Kp 不足 | ↑ Kp |
| 持续振荡 | Kp 过大 | ↓ Kp |
| 存在稳态误差 | Ki 为零或过小 | ↑ Ki |
| 超调后缓慢回落 | 积分饱和 | ↓ Ki 或 ↓ integral_limit |
| 到位后高频微振 | Kd 放大噪声 | ↓ Kd 或对传感器做低通 |
| 跟踪滞后显著 | Kp 不足或 Kd 过大 | ↑ Kp / ↓ Kd |

## 2. 异常排查

### 2.1 供电跌落复位

**现象:** 舵机动作瞬间 MCU 复位 (串口输出 Reset Source，OLED 闪屏，心跳停止)。

**根因:** SG90 堵转电流 >750mA。若从 STM32 3.3V LDO 取电，LDO 输出电流不足 → 电压跌落至 BOR 阈值 (~2.4V) 以下 → 系统复位。

**诊断:**
1. 万用表监测 STM32 3.3V 引脚在舵机启动时的电压
2. 电压 < 3.0V → 确认供电不足

**解决方案:**
1. 舵机必须使用独立 5V/2A 电源，与 MCU 供电物理隔离
2. 5V 输出端并联 470µF 电解 (储能) + 0.1µF 瓷片 (高频去耦)
3. MCU 端每个 VDD 引脚就近放置 0.1µF 瓷片电容
4. 所有模块的 GND 必须单点共地 (星形接地)

**进阶:** 若必须使用同一电源，在舵机供电回路串联 NTC 热敏电阻 (冷态 10Ω，热态 <1Ω) 抑制启动浪涌。

---

### 2.2 I2C 总线通信故障

**现象:** MPU6050 WHO_AM_I 返回 0xFF，OLED 不亮，程序卡在 I2C 初始化。

**排查路径:**

| 步骤 | 检查项 | 方法 |
|------|--------|------|
| 1 | 物理接线 | 万用表通断档验证 SDA/PB11, SCL/PB10 连通性 |
| 2 | 供电 | 测量各模块 VCC-GND = 3.3V ±0.1V |
| 3 | 上拉电阻 | 断电后测 SDA-VCC = 4.7kΩ (允许 2.2~10kΩ) |
| 4 | 地址冲突 | 仅保留 MPU6050，AD0 接 GND → 地址 0x68 |
| 5 | 时序裕度 | 增大 I2C_Delay() 延时 (nop 循环计数 ×2) |
| 6 | 从机故障 | 替换模块，单一变量法定位 |

**STM32F1 硬件 I2C BUSY 锁死:**

若使用硬件 I2C 替代本工程的软件 I2C，需注意: STM32F1 的 I2C 外设在从机异常复位或总线干扰后，BUSY 位可能永久置 1。此时必须在 I2C_Init 中执行软件复位序列:

```c
RCC_APB1PeriphResetCmd(RCC_APB1Periph_I2C1, ENABLE);
RCC_APB1PeriphResetCmd(RCC_APB1Periph_I2C1, DISABLE);
```

本工程使用软件 I2C，此问题不适用。

### 2.3 PID 控制发散

| 现象 | 诊断 | 修正 |
|------|------|------|
| 等幅振荡 | $K_p$ 过大 | 减半 $K_p$，观察 5 个周期 |
| 发散 (振幅越来越大) | $K_i$ 过大或 integral_limit 过高 | 降低 $K_i$，限制 integral_limit |
| 到位后微振 (buzzing) | $K_d$ 放大传感器噪声 | 降低 $K_d$，或对输入做低通 |
| 阶跃响应超调 >50% | 积分饱和 | 减小 integral_limit，或切换 setpoint 时清零积分 |
| 稳态误差 >3° | $K_i$ 不足 | 增大 $K_i$，每次 +0.01 |
| 舵机不响应 | 输出超出 0~180° 范围 | 检查 output_min/max 钳位 |

**VOFA+ 辅助诊断:**

| 波形特征 | 对应问题 |
|---------|---------|
| ch0 (滤波角度) 与 ch2 (原始角度) 差异大 | 互补滤波 α 值偏高 |
| ch5 (PID 输出) 频繁达到上下限 | 输出范围不足或 Kp 过大 |
| ch3/ch4 (陀螺仪) 噪声幅值 > 5°/s | 机械振动耦合，加固传感器安装 |

### 2.4 OLED 显示异常

| 现象 | 根因 | 解决 |
|------|------|------|
| 无显示 (全黑) | 电荷泵未开启 | 确认 0x8D→0x14 序列已执行 |
| 无显示 (全黑) | I2C 地址错误 | 测量 SA0 引脚电平: GND→0x3C, VCC→0x3D |
| 花屏/移位 | 初始化延时不足 | SSD1306 上电后 VDD 稳定需 ≥100ms |
| 局部缺行 | 页地址配置错误 | 检查 OLED_SetCursor page 参数 < 8 |
| 亮度过低 | 对比度寄存器 | 0x81 命令后跟值改为 0xFF |

### 2.5 VOFA+ 上位机配置 (完整步骤) 与串口异常排查

**协议说明:** 本工程使用 VOFA+ **FireWater** 协议的 ASCII CSV 格式——每一帧就是一行人眼可读的文本：

```
-1.23,4.56,0.00,12.34,5.67,0.00,0.45␍␊
```

7 个通道用逗号分隔，每行以 `\r\n` 结尾，帧率 20Hz (50ms 任务)。用任何串口助手打开都能直接看懂，这是 CSV 相对二进制格式 (JustFloat) 的最大优势——**调试时先用串口助手看原始文本，确认数据对了再开 VOFA+ 画波形**。

**VOFA+ 配置步骤:**

1. 下载安装 VOFA+ → 打开后点击左侧 **Data** 页
2. 协议选 **FireWater**（不是 JustFloat！JustFloat 是旧的二进制格式）
3. 选择你的 USB-TTL 串口号，波特率 **115200** → 点击连接
4. 右侧 **Widget** 页 → 拖入一个 **波形图** 控件
5. 波形图右上角 → 分配通道 (7 个) → 通道映射如下:

| 通道 | 数据 | 滤波链 | 参考幅值 |
|------|------|--------|---------|
| ch0 | pitch 俯仰角 | 互补滤波 | ±90° |
| ch1 | roll 横滚角 | 互补滤波 → 限幅(5°/步) → 滑动平均(8) | ±90° |
| ch2 | 加速度计俯仰角 | 滑动平均(8) | ±90° |
| ch3 | 陀螺仪 X (dps) | 无 | ±300°/s |
| ch4 | 陀螺仪 Y (dps) | 无 | ±300°/s |
| ch5 | PID 输出 | 无 | 0~180 |
| ch6 | ADC 电压 (V) | 中值(5) → 滑动平均(8) | 0~3.3 |

6. 拿稳传感器缓慢倾斜 → ch0/ch1 应出现平滑的正弦状波形；晃动传感器 → ch3/ch4 出现瞬态尖峰 (**这是真实角速度信号，不是故障**)

**串口异常排查表:**

| 现象 | 排查 |
|------|------|
| 串口助手全是乱码 | 波特率不是 115200，或 TX/RX 接反 |
| 串口助手正常、VOFA+ 无波形 | 协议选错 (应为 FireWater)；或未点击连接 |
| 波形帧断断续续 | DMA 拥塞：确认 `UART1_DMA_Update()` 每 50ms 被调用；检查 Task_50ms 是否被其他任务长时间阻塞 |
| 部分通道恒为 0 | 对应传感器未更新：ch5 恒 0 是正常的 (MODE_RUN 下 PID 被旁路)；ch3/ch4 恒 0 则检查 10ms 任务 |
| 波形毛刺特别多 | ch0/ch1 毛刺大 → 检查互补滤波 α 是否被改小；ch6 毛刺大 → 检查中值+滑动平均链是否被改动 |

### 2.6 编码器计数异常

| 现象 | 根因 | 修正 |
|------|------|------|
| 旋转无反应 | EXTI 中断未使能 | 检查 NVIC 配置 |
| 转 1 格跳多格 | 消抖时间不足 | 增大 ENCODER_DEBOUNCE_MS |
| 只能单向计数 | B 相未连通 | 测量 PB13 电平是否随旋转跳变 |
| 方向判断反了 | A/B 相接反 | 交换 A/B，或修改 ISR 中 `Bit_RESET` 判断分支 |

### 2.7 舵机故障排查

| 现象 | 根因 | 修正 |
|------|------|------|
| 上电瞬间 MCU 复位 | 舵机启动浪涌把电源拉低 (详见 2.1) | 独立 5V/2A 供电 + 470µF 电容 + 共地 |
| 舵机完全不动 | 信号线未接 PA0，或红黑线接反 | 查线：橙→PA0，红→外部5V，棕→GND |
| 舵机只在一个角度附近抖动 | PWM 信号幅值不足 (3.3V 推不动个别批次 SG90) | 加 1kΩ 上拉电阻到 5V，或用电平转换 |
| 舵机发热、发出"滋滋"声 | 目标角度频繁跳动 (PID 震荡/信号毛刺) | 检查 PID 参数是否发散；检查信号线是否远离舵机电源线 |
| 行程明显不足 180° | 供电电压低于 5V | 测舵机红线电压，负载下应 ≥4.8V |
| 断电后位置丢失、重新上电回中 | SG90 无位置反馈，这是**正常行为** | 上电自动归中 90° 是程序设计的保护动作 |
| 多个舵机同时动就复位 | 总电流超过电源能力 | 单个 SG90 峰值 ≈750mA，N 个舵机按 N×750mA 选电源 |

> **工作原理:** SG90 由直流电机、减速齿轮组与角度电位器构成内部闭环。PWM 高电平宽度 (0.5~2.5ms) 给定目标角度，电位器反馈当前位置，偏差驱动电机直至到达目标。控制帧周期固定 20ms (50Hz)。

## 3. 数字滤波体系说明

> **为什么要滤波？** MPU6050 的原始数据 = 真实姿态 + 各种噪声（振动、供电纹波、机械抖动）。滤波就是"从噪声里把真话听出来"。

本工程共 4 种滤波器，各司其职：

### 3.1 互补滤波 (姿态解算核心, 100Hz)

```
融合角度 = 0.98 × (上次角度 + 陀螺仪角速度 × 0.01s) + 0.02 × 加速度计角度
```

| 传感器 | 优点 | 缺点 |
|--------|------|------|
| 陀螺仪 | 瞬时响应快、短时间准 | 积分会累积漂移，几分钟能飘几十度 |
| 加速度计 | 长期绝对准 (靠重力方向) | 振动时噪声大、反应迟钝 |

**互补滤波的频域特性:** 陀螺仪积分短期精度高但存在漂移累积；加速度计由重力方向解算角度，长期绝对准确但受振动干扰。α=0.98 表示每 10ms 更新中陀螺仪积分权重 98%、加速度计修正权重 2%，对应时间常数 τ = α·dt/(1-α) ≈ 0.49s——漂移在约 0.5s 内被拉回真值。

### 3.2 滑动平均滤波 (MA_WINDOW = 8)

```
输出 = 最近 8 个样本的算术平均
```

- **优点:** 白噪声衰减 √8 ≈ 2.8 倍；O(1) 计算量（增量维护 sum，循环缓冲）
- **代价:** 群延迟 = (8-1)/2 = 3.5 个样本，在 20Hz 通道上约 175ms——所以只用于显示通道，绝不用于控制环路
- **用途:** ch1 (roll 显示)、ch2 (加速度计角)、ch6 (ADC 电压)

### 3.3 限幅滤波 (单步 5°)

```
若 |本次 - 上次| ≤ 5° → 原样通过；否则 → 只允许变化 5°
```

- **用途:** ch1 roll 通道的第一级——把一个孤立的 30° 毛刺"压扁"成 5°
- **设计要点:** 阈值必须大于真实信号的最大变化率（5°/50ms = 100°/s，远高于手晃动速度），否则会削掉真信号

### 3.4 中值滤波 (MEDIAN_N = 5)

```
取最近 5 个样本排序后的中间值
```

- **用途:** ch6 ADC 通道第一级——专治"孤立尖峰"（接触不良、静电、接线松动瞬间）
- **为什么和滑动平均级联？** 中值滤孤立毛刺，滑动平均滤持续白噪声，**两者各管一类噪声，先中值后平均**效果最好。单个滤波器顶不住两种噪声同时存在。

### 3.5 滤波链总览

```
ch0 pitch: MPU6050 ──→ 互补滤波 ──→ 波形 (无级联)
ch1 roll : MPU6050 ──→ 互补滤波 ──→ 限幅(5°) ──→ MA(8) ──→ 波形
ch2 acc  : MPU6050 ──→ atan2 解算 ──→ MA(8) ──→ 波形
ch3/ch4   : MPU6050 陀螺仪 ──→ 直通 (真实角速度，过滤=失真)
ch5 PID   : 直通 (控制量，滤波会引入滞后导致系统不稳)
ch6 ADC   : ADC ──→ 中值(5) ──→ MA(8) ──→ 波形
```

> **设计要点:** ch3/ch4/ch5 不加滤波的原因：陀螺仪角速度为瞬时物理量，滤波引入的相位滞后即失真；PID 输出位于控制环路内，滤波引入的群延迟会降低相位裕度并诱发震荡。显示通道允许滤波，控制通道必须保持原始数据。
