# 频率匹配与系统时序分析

## 1. 时序链路全景图

```
   MPU6050          互补滤波            PID              舵机              VOFA+
   (硬件)           (软件)            (软件)           (硬件)            (上位机)

  125Hz ───→  100Hz ───→  50Hz ───→  50Hz PWM ───→  20Hz
  采样率      解算率      控制率      执行周期      上报率

   8ms        10ms       20ms        20ms          50ms
   周期       周期       周期        周期          周期
```

## 2. 逐环节分析

### 2.1 MPU6050 采样: 125Hz (8ms)

**配置:**
- DLPF 带宽 = 5Hz (CONFIG = 0x06) → 内部采样率 = 1kHz
- SMPLRT_DIV = 7 → 输出率 = 1000 / (1+7) = **125Hz**
- 陀螺仪 ±2000°/s, 加速度计 ±16g

**选择理由:**
- 125Hz 对 STM32F103 (72MHz) 来说非常充裕，I2C 读取 14 字节仅需约 0.7ms
- 远高于人体运动频率 (手晃动最高约 5~10Hz)，满足奈奎斯特采样定理
- 5Hz DLPF 有效滤除传感器内部高频噪声，数据平滑

**数据读取方式:**
- 每次从 0x3B (ACCEL_XOUT_H) 连续读取 14 字节
- I2C 自动递增指针，一次传输获取全部 7 组数据
- 保证加速度和陀螺仪数据来自同一采样时刻 (同步性)

### 2.2 互补滤波: 100Hz (10ms)

**公式:**
```
angle = 0.98 × (angle + gyro × 0.01) + 0.02 × accel_angle
```

**频率关系:**
- 滤波频率 (100Hz) < 传感器刷新率 (125Hz)
- 每次滤波迭代总能读到新数据，不会重复使用同一帧
- dt = 0.010s 与任务周期完全一致，积分精度有保证

**计算量:**
- 加速度计角度: atan2f + sqrtf ≈ 800 个 CPU 周期
- 互补融合: 3 次浮点乘法 + 2 次加法 ≈ 200 个周期
- 单轴总计约 1000 周期 ≈ 14µs @ 72MHz，完全可以忽略

**α 值选取验证:**
```
τ (时间常数) = α × dt / (1-α) = 0.98 × 0.01 / 0.02 = 0.49s
```
即陀螺仪漂移在约 0.5s 内被加速度计拉回到真值。对姿态追踪而言，0.5s 的收敛时间足够快。

### 2.3 PID 控制: 50Hz (20ms)

**为什么 PID 频率是滤波的一半？**

| 考虑因素 | 说明 |
|---------|------|
| 舵机机械响应 | SG90 空载转速约 500°/s，20ms 可转约 10°，频率匹配 |
| 控制稳定性 | 滤波收敛后 (0.5s) 再进行 PID 计算，避免噪声驱动舵机抖动 |
| 抗混叠 | 滤波→PID 2:1 降频，相当于做了额外的低通滤波 |
| CPU 负载 | PID 单次计算约 10µs，50Hz 仅占 0.05% CPU 时间 |

**PID dt 参数的物理意义:**
```
积分: integral += error × 0.020  (每周期累加 20ms 的偏差)
微分: derivative = Δerror / 0.020  (20ms 区间的偏差变化率)
```
dt 必须与任务周期严格一致。如果改任务周期为 10ms，必须同步修改 dt=0.010，否则积分/微分系数实际效果会翻倍/减半。

### 2.4 舵机 PWM: 50Hz (20ms)

**硬件约束:**
- SG90 要求 PWM 周期必须为 20ms (50Hz)
- 脉宽 500~2500µs 对应 0~180°
- TIM2 配置: PSC=71, ARR=19999 → 1µs 精度，20ms 周期

**频率耦合分析:**
```
PID 50Hz → 舵机 50Hz → 完全同步
每周期 PID 输出一次新角度，舵机刚好收到一个新的 PWM 脉宽
如果 PID 100Hz 而舵机仍是 50Hz → 每两个 PID 输出只能生效一个 → 浪费
如果 PID 10Hz 而舵机仍是 50Hz → 舵机 5 个周期收到同一指令 → 响应迟钝
```

### 2.5 VOFA+ 串口上报: 20Hz (50ms)

**帧格式:** 6 通道 × 4 字节 float + 4 字节帧尾 = 28 字节/帧

**带宽占用:**
```
28 字节/帧 × 20 帧/秒 × 10 bit/字节 = 5600 bps
115200 bps 利用率 = 5600/115200 = 4.9%
```
DMA 非阻塞发送，串口几乎不占用 CPU。

### 2.6 OLED 刷新: 1Hz (1000ms)

**设计考量:**
- 人眼对文本刷新率要求低，1Hz 足够
- OLED 每次全屏刷新需 I2C 写入 1024 字节，约 80ms
- 放在低频任务中减少 I2C 总线占用，不干扰传感器读取

## 3. 各任务 CPU 时间预算

| 任务 | 周期 | 单次耗时 | 1秒内耗时 | CPU 占用率 |
|------|------|---------|----------|-----------|
| 10ms (传感+滤波) | 10ms | ~1.2ms | 120ms | 12% |
| 20ms (PID+舵机) | 20ms | ~0.02ms | 1ms | 0.1% |
| 50ms (VOFA+) | 50ms | ~0.1ms (DMA) | 2ms | 0.2% |
| 200ms (ADC+编码器) | 200ms | ~0.05ms | 0.25ms | ~0% |
| 1000ms (OLED) | 1000ms | ~80ms | 80ms | 8% |
| **合计** | — | — | ~203ms | **20.3%** |

> 剩余约 80% CPU 时间可用于扩展功能 (如蓝牙透传、SD 卡记录、更复杂的滤波算法等)。

## 4. 潜在频率失配风险

### 4.1 如果滤波频率 > 传感器采样率

```
假设: 滤波 200Hz, 传感器 125Hz
结果: 每 5ms 读一次 → 50% 概率读到同一帧数据 → 相当于 125Hz 采样的数据
      被错误地以 200Hz 频率积分 → 陀螺仪积分 dt=0.005 但数据实际间隔 0.008
      → 积分角度偏小 → 跟踪滞后
```

### 4.2 如果 PID 频率 >> 舵机响应速度

```
假设: PID 200Hz, 舵机响应 50Hz
结果: 舵机还未转动到目标角度就收到新指令 → 输出持续抖动
      D 项在噪声下被放大 → 舵机发热、滋滋响、寿命缩短
```

### 4.3 任务堆积风险

```
假设: 10ms 任务单次耗时 = 3ms, 而周期只有 10ms
结果: 当多个任务同时到期 (如 10ms 和 20ms 重叠)
      → 后到期的任务被延迟 → 实际频率低于设计频率

缓解措施:
  本工程 10ms 任务耗时 1.2ms，远低于 10ms 周期，
  即使所有 5 个任务同时到期，总耗时 <2ms（OLED 除外），
  OLED 在 1000ms 周期内，单次 80ms 也不会影响其他任务。
```
