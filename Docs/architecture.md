# 频率匹配与系统时序分析

## 1. 时序链路全景图

```
   MPU6050          互补滤波            PID              舵机              VOFA+
   (硬件)           (软件)            (软件)           (硬件)            (上位机)

  125Hz ───→  100Hz ───→  50Hz ───→  50Hz PWM ───→  20Hz
  采样率      解算率      控制率      执行周期      上报率

   8ms        10ms       20ms        20ms          50ms
   周期       周期       周期        周期          周期
```

## 2. 逐环节分析

### 2.1 MPU6050 采样: 125Hz (8ms)

**配置:**
- DLPF 带宽 = 5Hz (CONFIG = 0x06) → 内部采样率 = 1kHz
- SMPLRT_DIV = 7 → 输出率 = 1000 / (1+7) = **125Hz**
- 陀螺仪 ±2000°/s, 加速度计 ±16g

**选择理由:**
- 125Hz 对 STM32F103 (72MHz) 来说非常充裕，I2C 读取 14 字节仅需约 0.7ms
- 远高于人体运动频率 (手晃动最高约 5~10Hz)，满足奈奎斯特采样定理
- 5Hz DLPF 有效滤除传感器内部高频噪声，数据平滑

**数据读取方式:**
- 每次从 0x3B (ACCEL_XOUT_H) 连续读取 14 字节
- I2C 自动递增指针，一次传输获取全部 7 组数据
- 保证加速度和陀螺仪数据来自同一采样时刻 (同步性)

### 2.2 互补滤波: 100Hz (10ms)

**公式:**
```
angle = 0.98 × (angle + gyro × 0.01) + 0.02 × accel_angle
```

**频率关系:**
- 滤波频率 (100Hz) < 传感器刷新率 (125Hz)
- 每次滤波迭代总能读到新数据，不会重复使用同一帧
- dt = 0.010s 与任务周期完全一致，积分精度有保证

**计算量:**
- 加速度计角度: atan2f + sqrtf ≈ 800 个 CPU 周期
- 互补融合: 3 次浮点乘法 + 2 次加法 ≈ 200 个周期
- 单轴总计约 1000 周期 ≈ 14µs @ 72MHz，完全可以忽略

**α 值选取验证:**
```
τ (时间常数) = α × dt / (1-α) = 0.98 × 0.01 / 0.02 = 0.49s
```
即陀螺仪漂移在约 0.5s 内被加速度计拉回到真值。对姿态追踪而言，0.5s 的收敛时间足够快。

### 2.3 PID 控制: 50Hz (20ms)

**为什么 PID 频率是滤波的一半？**

| 考虑因素 | 说明 |
|---------|------|
| 舵机机械响应 | SG90 空载转速约 500°/s，20ms 可转约 10°，频率匹配 |
| 控制稳定性 | 滤波收敛后 (0.5s) 再进行 PID 计算，避免噪声驱动舵机抖动 |
| 抗混叠 | 滤波→PID 2:1 降频，相当于做了额外的低通滤波 |
| CPU 负载 | PID 单次计算约 10µs，50Hz 仅占 0.05% CPU 时间 |

**PID dt 参数的物理意义:**
```
积分: integral += error × 0.020  (每周期累加 20ms 的偏差)
微分: derivative = Δerror / 0.020  (20ms 区间的偏差变化率)
```
dt 必须与任务周期严格一致。如果改任务周期为 10ms，必须同步修改 dt=0.010，否则积分/微分系数实际效果会翻倍/减半。

### 2.4 舵机 PWM: 50Hz (20ms)

**硬件约束:**
- SG90 要求 PWM 周期必须为 20ms (50Hz)
- 脉宽 500~2500µs 对应 0~180°
- TIM2 配置: PSC=71, ARR=19999 → 1µs 精度，20ms 周期

**频率耦合分析:**
```
PID 50Hz → 舵机 50Hz → 完全同步
每周期 PID 输出一次新角度，舵机刚好收到一个新的 PWM 脉宽
如果 PID 100Hz 而舵机仍是 50Hz → 每两个 PID 输出只能生效一个 → 浪费
如果 PID 10Hz 而舵机仍是 50Hz → 舵机 5 个周期收到同一指令 → 响应迟钝
```

### 2.5 VOFA+ 串口上报: 20Hz (50ms)

**帧格式:** FireWater ASCII CSV——7 个通道每个用 `%.2f` 格式化为十进制文本，逗号分隔，`\r\n` 结尾。每帧约 50 字节 (随数值长度浮动)，例: `-1.23,4.56,0.00,12.34,5.67,0.00,0.45`

**带宽占用:**
```
50 字节/帧 × 20 帧/秒 × 10 bit/字节 = 10000 bps
115200 bps 利用率 = 10000/115200 ≈ 8.7%
```
DMA 非阻塞发送；CPU 侧开销为 20Hz × 7 次 snprintf，可忽略不计。

### 2.6 OLED 刷新: 1Hz 重建显存 + 200ms 分页输出

**设计考量 (framebuffer 架构):**
- 人眼对文本刷新率要求低，1Hz 足够
- 早期版本在 1Hz 任务里一次性整屏写入（清屏 1024 字节 + 全部字符），实测阻塞 ~750ms——协作式调度器被饿死 75% 的时间，滤波实际只跑到 ~25Hz
- 改为显存架构：Task_1000ms 只把内容画进 1KB RAM 显存（~µs 级）；Task_200ms 每次只推 1 页 (128 字节) 上屏
- 4 页 × 200ms = 800ms 完成整屏刷新，单次阻塞 ~50ms，被调度器自然吸收；整页覆盖式写入天然无残影，无需全屏清屏

**为什么整页覆盖无残影？** 每一页的 128 字节都来自当次显存内容，旧像素被整体替换——等效于"每页自带清屏"。

## 3. 各任务 CPU 时间预算

| 任务 | 周期 | 单次耗时 | 1秒内耗时 | CPU 占用率 |
|------|------|---------|----------|-----------|
| 10ms (传感+滤波) | 10ms | ~1.2ms | 120ms | 12% |
| 20ms (PID+舵机) | 20ms | ~0.02ms | 1ms | 0.1% |
| 50ms (VOFA+) | 50ms | ~0.1ms (DMA) | 2ms | 0.2% |
| 200ms (ADC+编码器) | 200ms | ~0.05ms | 0.25ms | ~0% |
| 200ms (OLED 分页×4) | 200ms | ~50ms | 200ms | 20% |
| 1000ms (显存重建) | 1000ms | ~0.1ms (RAM) | 0.1ms | ~0% |
| **合计** | — | — | ~323ms | **32.3%** |

> OLED 的 20% 来自软 I2C 当前 ~11kHz 的实际速率（设计 100kHz）。若提升 I2C 速度到设计值，该行会按比例降到 ~2%，总占用回落到 ~15%。剩余 CPU 时间可用于扩展功能 (如蓝牙透传、SD 卡记录、更复杂的滤波算法等)。

## 4. 潜在频率失配风险

### 4.1 如果滤波频率 > 传感器采样率

```
假设: 滤波 200Hz, 传感器 125Hz
结果: 每 5ms 读一次 → 50% 概率读到同一帧数据 → 相当于 125Hz 采样的数据
      被错误地以 200Hz 频率积分 → 陀螺仪积分 dt=0.005 但数据实际间隔 0.008
      → 积分角度偏小 → 跟踪滞后
```

### 4.2 如果 PID 频率 >> 舵机响应速度

```
假设: PID 200Hz, 舵机响应 50Hz
结果: 舵机还未转动到目标角度就收到新指令 → 输出持续抖动
      D 项在噪声下被放大 → 舵机发热、滋滋响、寿命缩短
```

### 4.3 任务堆积风险

```
假设: 10ms 任务单次耗时 = 3ms, 而周期只有 10ms
结果: 当多个任务同时到期 (如 10ms 和 20ms 重叠)
      → 后到期的任务被延迟 → 实际频率低于设计频率

缓解措施:
  本工程 10ms 任务耗时 1.2ms，远低于 10ms 周期，
  即使所有 5 个任务同时到期，总耗时 <2ms（OLED 分页除外），
  OLED 单次分页写入 ~50ms，即使与 10ms 任务同时到期，
  10ms 任务也只会被延迟一个周期，滤波频率影响 <5%。
```

> **真实案例 (本工程 2026-08-13):** 早期版本在 1Hz 任务里整屏刷新 OLED，实测阻塞 ~750ms/s，导致 10ms 任务实际只跑到 ~25Hz、互补滤波收敛慢 3 倍、VOFA+ 帧流每 1 秒断流 750ms。改 framebuffer 分页后彻底消除——这正是 4.3 节"任务堆积风险"的教科书实例。

## 5. 附录: 数字滤波器组架构 (VOFA+ 通道滤波链)

### 5.1 信号链全景

```
 l0 pitch: MPU6050 ──→ atan2/gyro ──→ 互补滤波(α=0.98,100Hz) ────────────→ 波形
 l1 roll : MPU6050 ──→ atan2/gyro ──→ 互补滤波 ──→ 限幅(5°/步) ──→ MA(8) ─→ 波形
 l2 acc_p: MPU6050 ──→ atan2 解算 ──→ 滑动平均 MA(8) ─────────────────────→ 波形
 l3/l4 gyro: MPU6050 角速度 ──────────────────────────────── 直通 ────────→ 波形
 l5 pid_out: PID 输出 ───────────────────────────────────── 直通 ────────→ 波形
 l6 adc_v : ADC(PA1) ──→ 中值(5) ──→ 滑动平均 MA(8) ────────────────────→ 波形
```

滤波执行位置: 互补滤波在 **Task_10ms (100Hz)** 内解算姿态；l1/l2/l6 的显示级滤波在 **Task_50ms (20Hz)** 内组装 VOFA+ 帧时执行。所有滤波状态均为 task_scheduler.c 中的静态变量，跨调用保持。

### 5.2 级联设计原理 (限幅 → 滑动平均)

roll 通道 (l1) 特意做成两级级联，**顺序不能颠倒**:

| 顺序 | 效果 | 问题 |
|------|------|------|
| 限幅 → 平均 (本工程) | 孤立 30° 毛刺先被压成 5°，再被平均窗口摊薄至 ~1° | ✅ 毛刺能量彻底挡在窗口外 |
| 平均 → 限幅 | 30° 毛刺先被 8 点平均摊成 ~4°，再进入限幅 | ❌ 限幅阈值 5° 时毛刺直接"漏网" |

**级联顺序分析:** 限幅对单样本步进量钳位，可将孤立大毛刺挡在滑动平均窗口之外；若顺序颠倒（先平均后限幅），毛刺能量被窗口摊薄后可能低于限幅阈值而漏过，滤波效果显著下降。

### 5.3 为什么 gyro / PID 通道不滤波

| 通道 | 不滤波的原因 |
|------|-------------|
| l3/l4 陀螺仪 | 角速度是**瞬时物理真值**，滤波等于篡改数据——VOFA+ 上看到的尖峰正是真实转动信号 |
| l5 PID 输出 | 控制环路内任何滤波 = 引入群延迟 = 降低相位裕度 = 诱发震荡。显示通道允许滤波，控制通道必须保持原始数据 |

### 5.4 滤波参数调节指南

| 参数 | 位置 | 调大 | 调小 |
|------|------|------|------|
| α (互补) | system_config.h `FILTER_DEFAULT_ALPHA` | 更信陀螺仪：动态响应快，但漂移收敛慢 | 更信加速度计：角度更稳，但振动噪声大 |
| MA_WINDOW | Filter.h | 更平滑，延迟更大 | 更灵敏，噪声更大 |
| 限幅阈值 | task_scheduler.c `LimitFilter(..., 5.0f)` | 允许更快变化 | 毛刺压得更狠，但真信号可能被削 |
| MEDIAN_N | Filter.h | 滤更宽毛刺，计算量增大 | 响应更快 |
